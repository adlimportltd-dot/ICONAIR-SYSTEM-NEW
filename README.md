# ICON AIR — מערכת ניהול שטח

ניהול קווי הפצה, מכשירים (Icon 300 / 500 / 700), מעקב שמנים וקריאות שירות.
React + Tailwind + Supabase, ממשק עברי מלא (RTL), עיצוב כהה glassmorphic.

---

## הפעלה — שלושה שלבים

### 1. בסיס הנתונים

ב-Supabase: **SQL Editor → New query**, הדבק את `iconair_schema.sql` (בתיקיית השורש
של הפרויקט) והרץ. קובץ אחד, אין קבצים נוספים להריץ אחריו — הוא יוצר את כל
הטבלאות, ה-enums, המפתחות הזרים, הטריגרים וה-RLS, כולל טבלת `profiles`
לתפקידים (מנהל/טכנאי). הסקריפט אידמפוטנטי — אפשר להריץ אותו שוב בלי לאבד נתונים.

אין נתוני דמו מובנים בסקריפט. המסכים יציגו מצבי "אין עדיין נתונים" עד
שתזין את הראשונים דרך הממשק עצמו.

לאחר שאתה והשותפים הרשמתם את עצמכם דרך מסך ההתחברות, הריצו את שתי שורות
ה-`update` שבסוף `iconair_schema.sql` (עם כתובות האימייל האמיתיות) כדי
לקבל הרשאת מנהל — כל מי שנרשם מקבל אוטומטית `technician`.

### 2. מפתחות

```bash
cp .env.example .env.local
```

מלא את שני הערכים מ-**Project Settings → API**:

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

> **רק המפתח `anon public`.** מפתח `service_role` עוקף את כל ה-RLS.
> כל מה שנמצא ב-`VITE_*` נארז לתוך ה-JS שרץ בדפדפן וגלוי לכל מי שפותח DevTools —
> אם מפתח service_role יגיע לשם, כל בסיס הנתונים פתוח לקריאה ולמחיקה.

### 3. הרצה

```bash
npm install
npm run dev      # http://localhost:5173
```

במסך הראשון הירשם עם אימייל וסיסמה. **המשתמש הראשון שנרשם מקבל אוטומטית
הרשאת מנהל**; כל מי שנרשם אחריו מקבל הרשאת טכנאי.

אם Supabase מוגדר לאמת אימייל ואתה רק בודק — כבה את זה ב-
**Authentication → Providers → Email → Confirm email**.

`server.host: true` כבר מוגדר, כך שאפשר לפתוח את המערכת מהטלפון
דרך כתובת ה-IP של המחשב באותה רשת — שימושי לבדיקת התצוגה בשטח.

## מבנה בסיס הנתונים

```
customers ──────< devices ──────< oil_tracking
   │                  │
   └──────< service_calls >────── devices

profiles ── auth.users (משתמשי Supabase; role: admin / technician)
```

אין טבלאות `routes` או `scents` נפרדות — קו ההפצה (`route_name`) והניחוח
(`scent_name`) הם שדות טקסט חופשיים על `customers`/`devices`/`oil_tracking`
בהתאמה. אין גם `views` בבסיס הנתונים; כל מדדי הדשבורד והדוחות מחושבים
בצד הלקוח מתוך שאילתות ישירות (`src/lib/queries.js`).

**החלטות שכדאי להכיר:**

- **הסטטוסים והדגמים הם `enum`, לא טקסט חופשי.** `Icon 700 ` עם רווח בסוף
  נדחה ברמת בסיס הנתונים ולא מגיע לדוח כשורה נפרדת.
- **`oil_tracking` הוא האמת ההיסטורית; `devices.oil_level_pct` הוא רק המצב הנוכחי.**
  טריגר מסנכרן ביניהם, כך שהיומן והמכשיר לא יכולים לסתור זה את זה —
  גם אם מישהו יכניס שורה ישירות מה-SQL Editor.
- **מספרים סידוריים וקודי קריאה נוצרים בבסיס הנתונים** (`ICN-700-0143`, `SC-2420`),
  לא בפרונט. שני משתמשים שפותחים קריאה באותה שנייה לא יקבלו את אותו קוד.
- **`service_calls` מחזיקה CHECK** שמוודא שקריאה סגורה תמיד עם `closed_at`
  וקריאה פתוחה תמיד בלעדיו. בלי זה חישוב ה-SLA היה משקר בשקט.

## אבטחה — מה מגן על הנתונים

ה-`anon key` נועד לרוץ בדפדפן וכל אחד יכול לקרוא אותו. מה שמונע ממנו
לשאוב את בסיס הנתונים הוא **Row Level Security**, והוא מופעל על כל טבלה:

| תפקיד | קריאה | הוספה | עדכון | מחיקה |
| --- | --- | --- | --- | --- |
| לא מחובר (`anon`) | ✗ | ✗ | ✗ | ✗ |
| טכנאי | ✓ | ✓ | רק רשומות שהוא יצר (`created_by`/`recorded_by`); בקריאות שירות — גם קריאות שמשויכות אליו | ✗ |
| מנהל | ✓ | ✓ | הכול | ✓ |

`created_by` (וב-`oil_tracking`: `recorded_by`) מתמלא אוטומטית עם `auth.uid()`
בזמן ההוספה — הפרונט לא צריך לשלוח אותו, וגם לא יכול לזייף אותו (יש `check`
על כך ב-RLS).

נקודה עדינה שכדאי לא לשבור: **`is_admin()` מוגדרת `security definer`.**
בדיקת התפקיד קוראת לטבלת `profiles`, שעליה יש RLS שקוראת שוב לבדיקת
התפקיד. בלי `security definer` זו לולאה אינסופית.

התפקיד נשמר בטבלת `profiles` ולא ב-JWT, כדי ששינוי הרשאה ייכנס לתוקף מיד:

```sql
update public.profiles set role = 'admin' where full_name = 'אבי כהן';
```

## מערכת העיצוב

הטוקנים ב-`tailwind.config.js`, בשימוש דרך מחלקות Tailwind רגילות.

| תפקיד | ערך | שימוש |
| --- | --- | --- |
| רקע | `ink-950 #08090B` | הקרקע העמוקה של המסך |
| זהב | `gold-500 #D8B36A`, `gold-300 #F0DCB4` | זהות המותג, מסך פעיל, דגם הדגל Icon 700 |
| טורקיז | `teal-500 #4CC9C0` | זרימת אוויר ושמן, Icon 500 |
| כחול-אפור | `slate-500 #6E86A8` | תחזית, Icon 300 |
| תקין / אזהרה / קריטי | `ok #4ED9A4`, `warn #F0A43A`, `crit #F0555C` | מצב בלבד — לא מעורבב עם צבע המותג |

**טיפוגרפיה** — שלושה תפקידים, וזו לא קוסמטיקה:

- `font-ui` (Assistant) — כל טקסט הממשק בעברית.
- `font-display` (Frank Ruhl Libre) — כותרות ומספרי-על. סריף עברי שנותן את הרובד היוקרתי.
- `font-mono` (IBM Plex Mono) — **רק לטינית וקודים** (`ICN-700-0142`, `SC-2419`). אין לו גליפים עבריים,
  ולכן טקסט עברי במחלקה הזו נופל בשקט לפונט ברירת מחדל ונראה שבור. לכל מספר שמופיע לצד עברית
  יש `.tabular` (tabular-nums) כדי שספרות יתיישרו בטור.

**נקודות שבירה** מכוונות לתוכן ולא לברירת המחדל של Tailwind:
`xs 560` שתי עמודות מדדים · `sm 680` שורת קריאה מלאה · `md 760` שדה חיפוש ·
`wide 960` שבב הצי החי · `lg 1080` מעבר מניווט תחתון לסרגל צד · `xl 1320` ארבע עמודות מדדים.

## עדכונים בזמן אמת

`service_calls` ו-`devices` נמצאות בפרסום ה-Realtime. קריאה שנפתחת מהשטח
מופיעה אצל המנהל בלי רענון, וכך גם מכשיר שיוצא מהרשת.

ה-RLS חל גם על Realtime — משתמש לא מחובר לא מקבל אירועים.
להוספת טבלה נוספת:

```sql
alter publication supabase_realtime add table public.customers;
```

## הערות נגישות ושטח

- הניווט התחתון מכבד `env(safe-area-inset-bottom)` — לא נחתך על אייפון עם notch.
- `prefers-reduced-motion` מבטל את אנימציות ההרמה והפעימה.
- לכל כפתור מצב `:focus-visible` בזהב, לעבודה במקלדת. Esc סוגר כל חלון קופץ.
- טבלה עם 7 עמודות הופכת לכרטיסים מתחת ל-680px, במקום גלילה אופקית.
- ייצוא ה-CSV נכתב עם BOM, אחרת Excel בעברית פותח ג'יבריש.
- ציר הזמן בגרף זורם משמאל לימין (`dir="ltr"`) גם בממשק RTL — כמו בכל כלי אנליטיקה.

## מה עוד לא נבנה

- מסך פרטי לקוח / מכשיר בודד (כרגע הרשימות בלבד).
- עריכה ומחיקה מה-UI — יש `updateCustomer` ו-`updateDevice` ב-`queries.js`, אבל אין להם עדיין מסך.
- העלאת תמונות מהשטח (Supabase Storage).
- מפת שטח אמיתית — הכפתור "מפת שטח" מוביל כרגע למסך המכשירים.
